# License and distribution scope

This repository contains three distinct categories of material. Keeping them
separate is necessary before any binary is published in a GitHub Release.

| Tree | Origin | License status | Distribution rule |
|---|---|---|---|
| `scripts/`, `src/`, `examples/`, `docs/`, `tests/test_*.py`, top-level build files | First-party work in this repository | MIT (`LICENSE`) | May be built and distributed under MIT, with notice |
| `reference/` | Archive supplied by the user, vendored for analysis | **No license file supplied** | Reading/reference material only; do not represent as MIT and do not ship linked binaries as MIT |
| `third_party/` | Generated by `scripts/bootstrap.sh` | EnTT MIT, fmt MIT/BSD-style exception, Zig MIT, CMake BSD-style | Not committed; restored per pinned checksum; see `THIRD_PARTY_NOTICES.md` |

The supplied `reference/baritone-android/` source is already in the repository,
but `docs/REFERENCE_BARITONE.md` explicitly records that the archive had no
license file and that vendored copies should be treated as reading material.
Accordingly:

- Local host builds may compile `reference/` for regression testing; this is
  development use inside the authorized repository.
- A release artifact must not contain object code derived from `reference/`
  unless the rights holder supplies a license permitting it.
- A release may contain first-party tools that are standalone and do not link,
  embed, or copy `reference/` source. Each such artifact carries `LICENSE` and
  a SHA-256 checksum.
- `third_party/` is ignored by Git and must be restored by the bootstrap script;
  its own licenses are retained in the extracted dependency trees.

No credentials, tokens, device dumps, or proprietary game binaries are stored in
this repository. The Android game binary (`libminecraftpe.so`) is not present and
is not required by the host test suite.
